# 双人开发需求与计划

## 目标和边界

在现有 TinyGPT、训练指标 API 和硬件监控页面上，完成可复现的本地训练监控闭环，再开展 Checkpoint 推理和网页文本生成。

团队成员为 DonZhong 与 DunhuaZhong。两人都可以提交和合并，采用独立分支、交叉评审和共同联调。以下负责人为建议初始分工，可在领取任务时互换；尚未完成的任务不代表已经承诺工期。

本轮不改模型架构，不引入多用户权限系统，不把基础语言模型标为已具备指令对话能力，也不把文档更新当作功能交付。

## 当前基线

依据 `main` 的 `589a149` 版本核对：

| 模块 | 已有实现 | 仍需完成或验证 |
| --- | --- | --- |
| TinyGPT | 字符分词、因果注意力、训练/验证、Checkpoint 保存及权重恢复 | 严格断点续训、独立推理服务 |
| Python 训练 | CLI、HTTP 创建实验、状态更新和指标上报 | 失败和中断时的状态收尾、API 故障行为验证 |
| 平台 API | 健康检查、实验创建/列表/状态、训练指标、硬件快照 | 完整训练到页面的复现验收 |
| 数据库 | PostgreSQL、初始表结构与硬件快照迁移 | 团队一致的初始化和迁移操作记录 |
| React 页面 | 硬件监控、实验选择、Loss/学习率/吞吐量展示与轮询 | 空态/错误态联调验证、前端 CI |
| CI | Python 自动化测试、后端容器构建和 API 冒烟检查 | 前端 lint/build 检查 |

“已有实现”来自源码检查，并不表示本机已跑通所有服务。每次交付记录实际执行结果。

## 任务交接与合并

每项任务记录以下内容，可使用仓库的 Issue 模板：

```text
需求 ID：
目标与用户可见变化：
负责人 / 评审人：
涉及目录与共享接口：
依赖：
验收条件：
验证命令与实际结果：
关联 PR：
状态：待领取 / 进行中 / 待评审 / 已合并 / 已验收
```

PR 合并后只标记“已合并”；需要联调的任务在完成实际验收后再标记“已验收”。任一成员都可在 CI 和同伴评审通过后合并，具体工作流见 [协作指南](../CONTRIBUTING.md)。
